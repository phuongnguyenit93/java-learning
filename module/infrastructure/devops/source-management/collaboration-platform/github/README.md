# Overview: Source Collaboration with GitHub

GitHub is a Git-backed repository hosting platform where teams can propose, discuss, review, and govern source changes. Git manages version history and the underlying operations; GitHub adds repository hosting, pull requests, access controls, reviews, and protection rules. Publishing a change is therefore different from having that change approved and accepted.

**Prerequisites:** Be comfortable with the basic Git ideas of repositories, commits, branches, and exchanging history. This module does not reteach Git commands.

**Learning path:** Begin with repositories, personal accounts and organizations, contributors, and pull request fundamentals. Then explore repository ownership and visibility, contributions through shared branches or forks, and the pull request review lifecycle. Continue to organization teams, repository roles, branch protection, and rulesets. Connect Issues and Releases before diagnosing a complete contribution-to-merge workflow.

**Learning outcome:** Identify GitHub collaboration objects and their scopes, choose an appropriate contribution path, interpret review evidence, diagnose why a merge is blocked, and locate the responsible platform controls.

**Boundaries:** Team branching policy belongs to Branching Strategy; Git command mechanics belong to Git. GitHub Actions pipelines, CI/CD, version management, and deployment belong to downstream modules. Issues and Releases are treated as repository collaboration surfaces rather than a complete project-management or release-engineering curriculum.
