# Overview — Source Management Fundamentals

**Source management** is how individuals and teams preserve, trace, and coordinate changes to source code so that everyone can identify which versions exist, where changes came from, and which changes have been accepted into shared source. Ad hoc file exchange makes it easy to lose work, confuse versions, and obscure responsibility.

**Prerequisites:** a basic understanding that a software project contains files that one or more people may edit. No Git commands, GitHub account, build tool, or deployment experience is required.

**Learning path:** begin with the concept, motivation, risks, and essential vocabulary; then understand version control and recorded history; compare centralized and distributed models; distinguish working files, local repositories, remote repositories, and accepted shared history. Next, separate version-control tools from collaboration platforms and team strategies. Finally, follow a governed change from being recorded to being shared, reviewed, and accepted. The chapters in the **Contents** follow this progression.

**Boundaries and next steps:** this module teaches the mental model, not Git syntax, vendor permission configuration, advanced branch policy, or pipeline implementation. Continue with **Git** for mechanics, then study one hosted platform such as **GitHub**, **GitLab**, **Bitbucket**, or **Azure Repos** for review and repository governance. Explore **branching strategy** and **monorepo/polyrepo** for team-level decisions. Once shared source has been accepted, building, testing, and delivering it belongs to **delivery automation/CI/CD**, outside this module.
