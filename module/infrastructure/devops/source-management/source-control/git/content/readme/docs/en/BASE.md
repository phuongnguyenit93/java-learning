# Git: Managing Source Change History

Git is a distributed version control system. This module focuses on **Git mechanics**: file states, staging, commits, references, branches, and how history is exchanged or recovered. The aim is to help learners explain and verify what Git records before coordinating changes with a team.

**Prerequisites:** basic familiarity with files, directories, a terminal, and source code. Prior knowledge of GitHub, GitLab, or release processes is not required.

**Learning path:** repository and three areas → creating commits and reading history → HEAD, branches, and tags → merges, conflicts, and cherry-pick → remotes, fetch/pull/push → rebase and history rewriting → stash, undo, and reflog → an end-to-end change scenario with observable evidence.

**Boundary:** this module teaches how Git behaves, not branch lifetime, Git Flow/trunk-based selection, or team merge policy. Pull/merge requests, permissions, and branch protection belong to hosted collaboration modules; CI/CD, release management, and deployment belong elsewhere. The eight chapters now teach commands, conditions, risks, observable Git state, and official sources to support practice in a disposable repository.
