## Quy trình build native được Boot hỗ trợ là gì?

<!-- VIDEO_SECTION -->

### Scene 1 — Quy trình build native được Boot hỗ trợ là gì?

**Time:** `00:00–00:32`

**Visual:**

Hai production lane dùng chung front half application → Spring AOT. Lane A qua Native Build Tools tới executable; lane B qua Buildpacks tới native OCI image.

**Script:**

Spring Boot có hai đường native production thực tế. GraalVM Native Build Tools tích hợp Maven hoặc Gradle để tạo native executable; Cloud Native Buildpacks của Boot có thể thực hiện native build trong builder rồi đóng executable vào OCI image. Cả hai đều phụ thuộc Spring AOT trước. Khác biệt chủ yếu nằm ở cách build và bàn giao native runtime, không phải ở việc có thể bỏ qua AOT hay closed-world model.

**Purpose:**

Đặt hai build lane được hỗ trợ và AOT prerequisite chung.

## Maven và Gradle tích hợp GraalVM Native Build Tools như thế nào?

### Transition

**Script:**

Đường tạo executable trực tiếp sẽ rõ hơn khi nhìn song song cách Maven và Gradle nối Spring AOT vào GraalVM Native Build Tools.

### Scene 1 — Maven và Gradle tích hợp GraalVM Native Build Tools như thế nào?

**Time:** `00:41–01:18`

**Visual:**

Maven: spring-boot-starter-parent native profile → process-aot → native:compile. Gradle: Spring Boot plugin + org.graalvm.buildtools.native → processAot dependency → nativeCompile. Ghi chú Maven không dùng parent phải cấu hình tương đương.

**Script:**

Với Maven kế thừa spring-boot-starter-parent, Boot cung cấp native profile để wire process-aot và mặc định của GraalVM Native Build Tools; direct executable có thể đi qua native profile và native:compile. Nếu không dùng parent, phải cấu hình tương đương cho Boot AOT và native plugin. Với Gradle, apply GraalVM Native Build Tools plugin cùng Spring Boot; Boot sẽ wire AOT task vào native build và nativeCompile trở thành entry point tạo executable. Invariant của cả hai là AOT trước, native compilation sau.

**Purpose:**

Dạy đầy đủ integration Maven và Gradle, gồm nativeCompile và setup khi Maven không dùng Boot parent.

Native Image nhìn chung không biến một build thành binary cho mọi platform, nên team thường build trên target platform hoặc môi trường tương ứng.

### Scene 1 — Tích hợp Buildpacks của Spring Boot tạo OCI image chứa native executable như thế nào?

**Time:** `02:48–03:20`

**Visual:**

Maven -Pnative spring-boot:build-image và Gradle bootBuildImage với GraalVM Native Build Tools plugin cùng đi vào Paketo builder, chạy AOT/native compile rồi tạo OCI image chứa executable.

**Script:**

Với Gradle, bootBuildImage tạo native image khi GraalVM Native Build Tools plugin đã được apply; nếu thiếu plugin, đường JVM image bình thường được dùng. Builder chạy AOT và native compilation rồi đóng executable vào OCI image. Registry, cache và Buildpacks mechanics tổng quát vẫn thuộc build-tooling-packaging.

**Purpose:**

### Scene 1 — Chạy native executable khác `java -jar` như thế nào?

**Time:** `03:32–04:07`

**Visual:**

Runtime comparison gồm command, process tree, external configuration inputs và gauge startup/memory/warm behavior dưới workload tương đương.

Khi so sánh hai dạng, hãy dùng cùng configuration và workload vì warm-up, diagnostics và memory management khác nhau; một con số idle process không đủ làm production verdict.
