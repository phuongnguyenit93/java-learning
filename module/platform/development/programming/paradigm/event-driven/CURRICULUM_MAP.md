# Event-Driven Programming — Curriculum Boundary

**Location:** `module/platform/development/programming/paradigm/event-driven`

**Purpose:** Organize behavior around events and handlers rather than assuming a single direct call sequence.

**Prerequisites:** Control flow, callbacks and basic application state.

**Owned topics:** Events, commands and state; Publishers, dispatchers and handlers; Event loops and queues; Ordering and reentrancy; Failures and handler lifecycle; Boundaries with Reactive and EDA; Design, testing and trade-offs.

**Out of scope / integration boundary:** Owns event loops, dispatchers, handlers, ordering, reentrancy and lifecycle; distinct from Event-Driven Architecture between services and from Reactive Streams subscription/backpressure.

**Source of truth:** `content/roadmap/vi/roadmap.yml` and `content/roadmap/en/roadmap.yml`. Future Knowledge/Menu and assessments must follow their approved scope; do not assume that content has been generated simply because the module exists.
