# Dataflow Programming — Curriculum Boundary

**Location:** `module/platform/development/programming/paradigm/dataflow`

**Purpose:** Represent computation as nodes and data-dependency edges where work becomes eligible when its inputs are available.

**Prerequisites:** Functions, data structures and simple dependency graphs; functional and imperative concepts help comparison.

**Owned topics:** Dataflow model and dependency graphs; Execution readiness; Graphs, cycles and feedback; Dependency-driven parallelism; Determinism and state; Batch and streaming dataflow; Applications and trade-offs.

**Out of scope / integration boundary:** Distinct from Data-Oriented Programming (data representation), Reactive Programming (signals over time/backpressure) and general workflow orchestration. Owns dataflow graphs, readiness, scheduling and determinism, not a specific pipeline framework.

**Source of truth:** `content/roadmap/vi/roadmap.yml` and `content/roadmap/en/roadmap.yml`. Future Knowledge/Menu and assessments must follow their approved scope; do not assume that content has been generated simply because the module exists.
