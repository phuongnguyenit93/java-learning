# Abstraction, Abstract Classes, and Interfaces

This module builds the mental model for **abstraction in Java**: separating what an object must do from how it does it, then expressing that contract through abstract classes and interfaces.

## Why learn this module?

Memorizing `abstract` and `interface` syntax is not enough to choose a good design. The goal is to understand the trade-offs among shared state and implementation, contracts, multiple type inheritance, and API evolution.

## Learning flow

Study the module in this order:

1. why abstraction exists;
2. abstract classes and shared implementation/state;
3. interfaces as contracts;
4. abstract class versus interface;
5. interface inheritance;
6. default, static, and private interface methods;
7. multiple inheritance through interfaces and conflict resolution;
8. a final decision model for choosing the right abstraction.

## Module boundary

This module focuses on Java Core abstraction mechanisms. Broader OOP reasoning, class/object lifecycle, and polymorphism are developed in their dedicated modules. By the end, the learner should choose abstract classes or interfaces from design requirements rather than habit.
