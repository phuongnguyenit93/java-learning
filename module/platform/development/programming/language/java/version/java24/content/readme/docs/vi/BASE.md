# Java 24 — Các cải tiến còn giá trị trên JDK hiện đại

Java 24 tiếp tục phát triển Java ở cả thư viện, JVM và công cụ triển khai: xử lý dữ liệu theo luồng linh hoạt hơn, thao tác class file bằng API chuẩn, cải thiện khả năng mở rộng của luồng ảo và bổ sung các thuật toán mật mã hậu lượng tử. Module này tập trung vào **những thay đổi có thể vận dụng trên JDK hiện hành**, không khuyến khích dựa vào cơ chế nội bộ hay API thử nghiệm đã đổi khác. Bạn sẽ học cách nhận diện mục tiêu của từng cải tiến, xác minh mức hỗ trợ của bản JDK đang sử dụng và đo lường hiệu quả thay vì mặc định tính năng mới luôn phù hợp mọi trường hợp.

Nội dung dành cho người đã có nền tảng về Java Streams, xử lý đồng thời, class file và kiến thức cơ bản về JVM. Trước tiên, bạn sẽ dùng **Stream Gatherers** như `windowFixed`, `windowSliding`, `scan`, `fold` và `mapConcurrent`, kết hợp bằng `andThen` và hiểu trạng thái cùng điều kiện dừng của gatherer tự viết. Tiếp đó, **Class-File API** với `ClassFile` và `ClassModel` giúp đọc, tạo hoặc biến đổi bytecode qua giao diện chuẩn và kiểm tra kết quả hợp lệ. Về đồng thời, bạn sẽ tìm hiểu cải tiến của **virtual threads khi chờ trong khối `synchronized`**, phân biệt hiện tượng giữ carrier thread với tranh chấp khóa và quan sát trên tác vụ I/O. Phần **AOT cache** hướng dẫn thực hiện chạy huấn luyện, tạo bộ nhớ đệm nạp/liên kết lớp và so sánh thời gian khởi động có hoặc không có cache.

Ở các mốc vận hành, bạn sẽ xem xét **ZGC theo chế độ phân thế hệ**, dùng số đo CPU, độ trễ, thông lượng và bộ nhớ để lựa chọn giữa G1 và ZGC. Về an toàn mật mã, bạn sẽ phân biệt **ML-KEM** dùng đóng gói khóa với **ML-DSA** dùng chữ ký số, thực hành các API `KEM` và `Signature` tương ứng. Bạn cũng sẽ tìm hiểu các cảnh báo và cơ chế cấp quyền truy cập native với **JNI/FFM**, ưu tiên API được hỗ trợ như `VarHandle` hoặc FFM thay vì truy cập bộ nhớ bằng API nội bộ. Cuối cùng, bạn sẽ dùng **`jlink`** tạo runtime image theo mô-đun, kiểm tra phụ thuộc và xác nhận khả năng liên kết không cần JMOD trên bản JDK đang dùng. Hoàn thành module, bạn có thể áp dụng các cải tiến Java 24 có cơ sở, kiểm chứng chức năng và đánh giá chi phí vận hành bằng số liệu thực tế.
