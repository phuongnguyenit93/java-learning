# Identity and Equality

## <a id="identity-vs-equality">Object identity vs logical equality</a>
Identity asks whether two references designate the same object. Logical equality asks whether two objects should be considered equal according to domain/value semantics. Java exposes identity through reference `==` and gives classes `equals` as the overridable logical-equality hook.

## <a id="reference-equality">Reference equality with ==</a>
For reference values, `==` compares identity (or both null), not object content. It is appropriate for enum constants, singleton identity, sentinel objects, or explicit identity questions. It is usually wrong for value-like objects such as strings, money values, or IDs.

## <a id="value-object-equality">Value-object equality mental model</a>
A value object is identified primarily by its meaningful values rather than object identity. Its equality should normally be stable, symmetric, and based on immutable/effectively immutable components. Equality design is part of the domain contract, not just boilerplate generated by an IDE.
